# Intelligent Document Question Answering System

Ask questions about any PDF and get answers grounded in its content. This project uses **Retrieval-Augmented Generation (RAG)** with a **local LLM (Llama 3 via Ollama)**, so everything runs on your own machine: no API keys, no cloud costs, and your documents stay private.

## Features

- Upload a PDF and extract its text
- Split text into overlapping chunks for better context retention
- Generate semantic embeddings with Sentence Transformers
- Fast similarity search using a FAISS vector index
- Answers generated by a local Llama 3 model, restricted to the retrieved context
- Shows the retrieved context so you can verify every answer
- Fully offline after the initial model downloads

## How It Works

```text
PDF Upload
    ↓
Extract Text (PyPDF2)
    ↓
Split into Chunks (500 chars, 100 overlap)
    ↓
Create Embeddings (all-MiniLM-L6-v2)
    ↓
Store in FAISS Index
    ↓
User Question → Embedding → Top-3 Similar Chunks
    ↓
Context + Question → Llama 3 (Ollama)
    ↓
Final Answer
```

If the answer is not present in the document, the model is instructed to reply:
*"I could not find the answer in the uploaded PDF."*

| Component | Technology |

## Prerequisites

- Python 3.11 or higher
- [Ollama](https://ollama.com) installed and running
- At least 8 GB RAM (16 GB recommended)

## Installation

1. **Clone the repository**
   ```bash
   git clone https://github.com/<your-username>/<your-repo-name>.git
   cd <your-repo-name>
   ```

2. **(Recommended) Create a virtual environment**
   ```bash
   python -m venv venv
   venv\Scripts\activate        # Windows
   source venv/bin/activate     # macOS / Linux
   ```

3. **Install dependencies**
   ```bash
   pip install -r requirements.txt
   ```

4. **Download the LLM**
   ```bash
   ollama pull llama3
   ```
   Make sure Ollama is running in the background (`ollama list` should show `llama3`).

## Usage

```bash
streamlit run app.py
```

Open `http://localhost:8501` in your browser, then:

1. Upload a text-based PDF in the **Upload PDF** tab.
2. Wait for "Vector database created successfully!".
3. Type your question and press Enter.
4. Read the generated answer, and expand **Retrieved Relevant Context** to see the source text.

## Configuration

| Setting | Location | Default |
|---|---|---|
| Chunk size / overlap | `split_text_into_chunks()` | 500 / 100 characters |
| Retrieved chunks | `search_relevant_chunks(top_k=...)` | 3 |
| Embedding model | `load_embedding_model()` | `all-MiniLM-L6-v2` |
| LLM | `ask_llm()` → `"model"` | `llama3` |

On low-RAM machines, use a smaller model such as `llama3.2:1b` or `llama3.2:3b` and update the `"model"` value in `ask_llm()`.

## Limitations

- Scanned (image-only) PDFs are not supported because no OCR is included.
- The vector index is kept in memory, so it is rebuilt each time the page reloads.
- Only one PDF can be queried at a time.
- Answer speed depends on your CPU/GPU; CPU-only machines may take from tens of seconds to a couple of minutes.

## Troubleshooting

| Problem | Fix |
|---|---|
| "Ollama is not running" | Start the Ollama app, or run `ollama serve` |
| "No readable text found" | The PDF is likely scanned; use a text-based PDF |
| `streamlit` not recognized | Run `python -m streamlit run app.py` |
| Very slow answers | Use a smaller model (see Configuration) |
